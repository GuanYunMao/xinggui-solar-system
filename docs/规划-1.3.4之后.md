# 规划评审：1.3.x 收束之后

写给检查用。分三块：现在这一版实际是什么、后面三代怎么排、哪些旧说法已经作废。

---

## 一、现在这一版（1.3.4）

### 玩起来是什么样

两个模式，一个开关：三条校准门各发生一次之后，沙盘与实境可以随时互切。

- **沙盘**：8 颗行星 + 6 颗卫星，共面正圆，点开看资料卡。追求可读，不追求真实比例。
- **实境**：地月 + 冥王星 + 哈雷，1:1、六根数、开普勒解。时间冻结，相机只有地球／月球两个取景。

### 三条门现在判什么

| 门 | 判据 | 玩家要做的 |
| --- | --- | --- |
| 时间 | 月球进入地球本影，且进去那一帧月球被选中 | 点地球 → 卫星行点月球 → 等最多 7.5 秒 |
| 目标 | 玩家自己选中水星并看满一整圈 | 点水星 → 盯住别换，8× 约 20.8 秒 |
| 图层 | 名称与轨道都关闭后，在画布上点中一颗行星 | 关两个开关 → 在 3D 里点中一颗 |

深链（`?body=moon` 这类）不算数：选中来源分成 url / canvas / hud 三种，门只认对应的那种。

### 门禁

- `verify`：36 条断言，`failures: []`，284.1 秒，绑在 `index-Dber-L_Y.js` 上
- `check-shape`：0 失败 / 5 通过 / 4 vacuous（那 4 条由 `--selftest` 证明仍会红）
- 产物：`release/巡星.html` 1,513,609 B，sha256 `6F753CDC…528E`
- 提交 `40a1da0`，tag `v1.3.4`

### 已知问题（不阻塞，档案在这里）

1. 规则行写「8×/1×」，HUD 滑条写「×8/×1」，两处不统一。属文案债。
2. 「明暗走完一轮」的可见周期只有一次像素采样支撑（峰间距 8.17 模拟秒 vs 模型 8.2，偏差 0.4%），采样分辨率 ±0.1 模拟秒，1.4.0 判读时复核。
3. 卡片仍印真实资料（距日、公转）。门·目标的「是哪颗」因此仍可查卡——这是明确接受过的取舍，不是漏改。

## 二、1.4.0：第一次能飞

### 目标

从「看得见」到「到得了」。这一版之后，玩家第一次能离开地月。

### 进什么

| 项 | 具体 |
| --- | --- |
| 实境星空层 | 天球半径 = `far / 1.2`；纯方向场，缩放不产生像素位移；几何体一次建好 |
| 飞行动作 | 选目标（单击不瞬移）→ 按住推进 → 到达 1.2R（= 7.645e6 m） |
| 到达耗时 | 地球 56.78 秒、月球 66.36 秒、冥王星 179.92 秒（当前历元实测） |
| 观测记录 | 天体 → 可测量量 → 观测次数 → 解出的值；停留 5 秒自动生成，无确认键 |
| 冥王星取景 | focus 1.5e9 → 1.2e7，盘面 0.74 px 变 93.3 px |
| 哈雷 | 数据保留，从 build 摘除（focus 5e8 下只有 0.0103 px） |
| 真实地球光照 | 只做晨昏线。夜面城市灯、海面镜面、地形法线挪到 1.5.0 |

### 不做什么

主带、柯伊伯、星图、发现机制。也不给 `?proto=1` 挂星空——挂上之后抖动判据不会以「超标」变红，会以「像素回读采不到样本」变红，形态变了容易被当成夹具坏了。

### 验收口径

1. 从太阳系连续缩放到近地表面（HANDOFF 提案 2）
2. 抖动：`p10–p90 ≤ 5 × 噪声底`，必须在 `dist = 1.2e7` 的标定点上量；1.8e7 那档的底是标定点的 6.1 倍
3. 帧率：30 fps / p95 ≤ 33.3 ms，只在 Intel Arc 130T 真机量
4. 星空层到位后重测实境亮度（现在实测 8.94，沙盘同口径 18.56）

### 风险

- 抖动阈值：底是夹具点专用常数，换视口或换 dist 都要现量
- 近地面取景：1.2R 下地球盘面 1407 px 占满 720 行，星空不可见，还会 5 秒就自动生一条地球落点
- 检查器只能验内部自洽：算术复算抓得住「表里前后矛盾」，抓不住「前提压根不对」

### 发版后审计带出来的四条输入（不拖交付，1.4.0 开工时权衡）

1. target 提示点名水星，识别环节退成了告知。想恢复「自己找」得走字段门控——这与本版的取舍正好相反，值不值在 1.4.0 再算。
2. 「明暗走完一轮」的可见周期只测过一次（174 点采样，分辨率 ±0.1 模拟秒），要更硬的证据得加采样密度。
3. 规则行「8×/1×」与 HUD 滑条的「×8/×1」写法不统一。
4. wide 下最小画布目标只有 3.2 px；target 在 8× 下要等 21 秒；面板 +43 px（320 仍不溢出）。可考虑命中宽容、进度提示，或压缩规则行。

## 三、1.5.0：主带与发现

### 定位

主带四颗（谷神星、灶神星、智神星、健神星）+ 柯伊伯三颗（阋神星、妊神星、鸟神星）作为**更多可被观测、可测量的内容**进来，不是「多七颗摆着」。

### 进什么

| 项 | 具体 |
| --- | --- |
| 观测累积 | 多次观测自动解轨道，不再靠卡片 |
| 线索 | 天区 + 日期，不给坐标。开发者手填的线索就是 No Man's Sky 的「36 小时 nothing to show」 |
| 七颗天体 | 每颗至少三个可测量量：视位置（相对背景恒星的移动）、角径、亮度与相位角、自转光变周期（小行星才有） |
| 沙盘同步 | 实境探到之后才在沙盘出现，表现同现有 8 颗 |
| 卡片照片 | 探测器真实影像，标出处，先算等效分辨率再选图 |
| 星图 | 从 2 代际提前——它不是装饰，是这套观测玩法要用的仪器 |

### 不做什么

奥尔特云、结局、地表。

### 验收

七颗都能被观测到（不是看不见的数据点）；每颗至少三个可测量量；测到阈值自动落记录、无确认键；同一颗隔很久再测，两次值不许打架。

### 小天体在沙盘怎么看见（已定）

按用户 2026-10-25 的定法：**靠顶上那份可拉开的星球列表，加上它自己的轨道线。**

不做最小可见尺寸（把谷神星放大到比真实大，等于在沙盘里撒谎），也不做注记点层（哈雷那种 6 px 的 UI 点是为「彗核在实境里亚像素」准备的，沙盘不需要）。

代价与待解：列表会从 9 项涨到 16 项，窄屏需要分组或二级（主带一组、柯伊伯一组）。这条在 1.5.0 开工时定。

## 四、1.6.0：边界与收束

### 进什么

离散盘、更多周期彗星、奥尔特云、比例尺 AU → 光年、结局三拍、测绘完成判据。

### 结局不许加的东西

不加新天体、不弹警报、不宣布下一个目标、不写「尚未探索」、不暗示外面还有恒星等着发现。

### 硬约束

这是一次性作品。市场侧的证据：撑时长只有三种机制——知识闭包、规模与署名、实时事件。我们只有 15 个天体，堆不了规模；所以走知识闭包（一次性）+ 实时事件（真实天象）。结局之后不再加清单，否则「测绘完成」会变成作业。

---

## 五、2 代际：远征

星图、程序生成星系、线索扫描、图鉴，走出太阳系。

前提是 1.4–1.6 把双模式规则跑通：实境是探索发生地，沙盘是已发现内容的显示面。这条不成立，2 代际只是把太阳系换成更大的太阳系，玩法不变。

## 六、旧说法作废清单

| 旧说法 | 出处 | 现状 |
| --- | --- | --- |
| 沙盘不跟着扩，保持 8 颗行星加卫星 | ROADMAP、原设计文档 | 作废。沙盘随探索扩，新内容实境探到后才出现 |
| 实境默认接近纯黑 → 1.4.0 自由飞解决 | 设计文档「已知问题」表 | 作废。自由飞只会更黑，缺的是星空层。以 HANDOFF 为准 |

| 三条提示 = 三条可执行的观察 | 1.3.0 CHANGELOG | 已实现为三条判据，文案见 1.3.4 |

## 七、已拍定的三件（2026-10-25）

1. **沙盘呈现**：可拉开的星球列表 + 天体自己的轨道线。不做最小可见尺寸，不做注记点层。见第三节。
2. **1.4.0 光照让步**：通过。只做晨昏线，夜面城市灯、海面镜面、地形法线挪到 1.5.0。
3. **1.6.0 的终点站问题**：挂起，不拍。

### 挂起那条的连带影响

用户原话的意思是：2 代际不会那么快上线，所以第一个版本的玩法后面可能还要加。因此：

- 1.6.0 的**结局三拍照做**——那是这一代的最收束，写好了就该收；
- 但版本线**不声明「到此为止」**。结局之后不塞清单、不写「尚未探索」，可也不关闭后续往 1.x 里加玩法的门；
- 判定标准只有一条：**加的是「怎么观察」，不是「更多内容」。** 前者可以一直加，后者我们已经证明过没有市场先例。
