# 规划 v2：实现优先

## 为什么重做

上一轮两天：4291 行改动，玩家看得见的 **43 行**（1.0%）。`SolarCanvas.tsx` 与 `textures.ts` 的 diff 是 0——渲染层一行没动。

根因不是没干活，是把「评审通过」当成进展：任务板 37 条，换算成玩家能看见的变化，只有三句面板文案。旧版本线里真正改画面的是 1.4.0，而它两天里一行代码没写。

## 三条新规则

1. **每个版本的验收第一条必须回答「玩家打开能看到什么」。** 这句话写不出来，这个版本不做。
2. **同一时间最多一个实现任务在飞。** 做完立刻 build，先给人看，再谈评审。不再先出规格、再走六轮评审、最后才动手。
3. **网站是主形态。** 单文件 HTML 降级成离线备选，不再是交付重心。

## 1.4.0 · 能飞

**玩家能看到**：进实境有星空；选一颗天体，按住推进，真的会飞过去；到了之后卡片上多一行「首次到达 · 第 N 日」。

- 星空层（上面的数）
- 飞行动作：选目标（单击不瞬移）→ 按住推进 → 到达 1.2R。地球 56.78 秒、月球 66.36 秒、冥王星 179.92 秒
- 观测记录：停留 5 秒自动落一条，无确认键
- 冥王星取景按钮（focus 1.5e9 → 1.2e7）；哈雷从 build 摘除
- 晨昏线光照（夜灯/镜面/法线推迟）

不做：主带、柯伊伯、星图、发现机制。

星图、程序生成星系、线索扫描、图鉴。前提是 1.4–1.6 的双模式规则跑通：实境是探索发生地，沙盘是已发现内容的显示面。

## 停掉的东西

- 多 agent 互相派任务、自动修复/复审的回合循环
- 「先出规格、评审六轮、再实现」的串行
- 把文档当交付（规格可以写，但不能代替画面）
- 1.7.0 那个「改独立 Web App」的版本：网站现在就上，不需要单独一个版本

## 版本线的判据

每个版本发版时问一句：**这一版玩家打开，和上一版比，第一眼能看出什么？**

答「看不出」的版本，不发。
